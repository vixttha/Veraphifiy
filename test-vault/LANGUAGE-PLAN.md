# Graphify HQ test language plan

This plan maps all 14 language tracks in the [pinned Lydite v0.0.4 inventory](https://github.com/vixttha/Lydite-Test-Vault-Template/tree/87d25d80d3154d295052412b64b29a0f0f152c27/languages). The audited Graphify HQ baseline is [424d86c](https://github.com/vixttha/Graphify-HQ/commit/424d86c6581b496bac7feb590b1512eeb11ac569). Its [case catalog](cases.md) has 77 checks across six languages, confirmed by the [public Ubuntu and Windows run](https://github.com/vixttha/Graphify-HQ/actions/runs/44514338567).

The 120 cases below are proposed. There are 72 proposals across the six active languages and 48 across eight adopter languages. The [language audit](LANGUAGE-AUDIT.md) identifies reproduced gaps and the cases that address them. Register a proposed ID in the executable catalog once the named assertion runs through a real entry point and produces a verifiable result. The active runner reconciles named results with the catalog. An additional language needs a runner result the reconciler can recognize when that language is adopted.

## Build order

1. Start with the reproduced integrity gaps. GHQ-PY-035 protects the previous archive during failed journal recovery. GHQ-JS-013 through GHQ-JS-019 check wire integrity. GHQ-TS-013 and GHQ-TS-015 check citation integrity. GHQ-PY-032 and GHQ-PY-033 tighten the observed bundle and named compiler evidence.
2. Exercise the remaining active fixtures in the same six suites. Use standard public GitHub-hosted Ubuntu and Windows for public fixtures. Verify live public PR provenance and public runner routing independently of local doubles. GHQ-SH-008 requires an existing private self-hosted runner and a dedicated private fixture.
3. Adopt an additional track when its named entry point is present. Keep a passing control and an isolated negative fixture. Record the case ID, exact checkout SHA, dependency and runtime versions, and a native named result. Suites that share an observation report the same Lydite case-plan and evidence digests. When a proposed case specifies a new behavior, pin that behavior before promoting the case into CI.
