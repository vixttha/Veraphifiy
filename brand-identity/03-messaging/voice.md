# Slogan and voice

**Lead slogan.** A map with receipts.

**Descriptor.** Code memory for each project version.

**README opener.** “Veraphify gives coding agents a code memory for each project version. Each archived version has its own Graphify map tied to its source commit. An agent can start with the version it is working on, look up how its features work, and follow the evidence to source code, tests, and verification records.”

**Upstream attribution.** “We use and support the open-source Graphify project. Veraphify is developed and maintained independently of Graphify Labs.” [Graphify upstream repository](https://github.com/Graphify-Labs/graphify)

| Slogan option | Three readings |
| --- | --- |
| **A map with receipts.** | The map shows relationships. The receipt records verification. The two together let someone else check what the map represents. |
| **Follow it to the source.** | Start from a feature and follow a graph relationship. Open the original code at the cited line. Use the exact commit as the reference when verifying a claim. |
| **Every link leads somewhere.** | A graph link reaches another entity. A source link can be opened and inspected. An evidence link gives a reviewer somewhere concrete to go next. |

Use the lead slogan in an overview if it helps orient readers. Use the factual descriptor for repository descriptions and the headline for documentation. Write short sentences that lead with the result, then identify the evidence.

- **Example guidance.** “Open BART’s archived v0.0.8 graph and check its companion receipt for the source commit.”
- **Example status copy.** “The receipt records a different source commit. Compare its SHA with the graph before using this evidence.”

The [pinned evidence archive](https://github.com/vixttha/Blender-Agent-Refinement-Toolkit/tree/6af3c2025be3f51e02dca4e4502088c526aae6d1/graphify/v0.0.8) shows a graph paired with a receipt. The [Test Vault record](https://github.com/vixttha/Veraphify/blob/3651503ad22a9db480dc8eb31c17599803f35ae8/test-vault/README.md) documents the verification scope. Use examples with an inspectable source. Phrase test links as test definitions unless a run receipt records the result.
